Date: 2026-08-20

## 1. Why this pass was needed

Two prior QA passes ended with the same unresolved criticism: garments read as flat
rectangular cut-outs. Both attributed it to the placeholder media having no alpha channel, and
recommended alpha-masked test artwork as the fix.

That diagnosis was correct but incomplete. Adding alpha artwork alone would have changed nothing,
because **three separate defects sat between an assigned artwork ref and a rendered silhouette**.
All three are fixed here, and each is covered by a test that fails without the fix.

## 2. What was actually broken

### 2.1 Garment artwork was never scheduled for loading

`spatialMediaPlacementIdsToLoad` selected items by `item.media` — the placement's single media
ref. Garment artwork does not live there; it lives on the garment channels
(`frontMedia` / `backMedia` / `displayMedia` / …). So **no garment was ever scheduled for texture
loading**, and every garment kept the procedural placeholder texture, which is a filled
rectangle.

This is the direct cause of "garments look like rectangular cards". It was not the media's fault:
no assigned artwork of any kind, alpha or not, could ever have appeared.

### 2.2 The artwork override was written but never read

`SpatialMediaBinding.mediaOverride` — added by the garment-carrier pass to carry a garment's
front/back artwork — was populated at registration and then **never consumed**. The loader
resolved `binding.item.media` instead, so even a scheduled garment would have fetched the wrong
ref (or none).

### 2.3 The contain step painted over the alpha

`createContainedMediaTexture` filled the whole canvas with opaque `#111318` before drawing the
image. That backing is correct for a projection wall or poster — the letterbox bars must not be
see-through — but for garment artwork it destroyed the alpha channel before `alphaTest` ever saw
it, leaving an opaque card behind every garment.

The fill is now conditional on whether the surface is an alpha artwork surface, threaded through
as `SpatialMediaBinding.alphaArtwork`.

### 2.4 A fourth defect found on the way: bound shoes lost their artwork

`bindArrangerPieceToHost` copied only `frontImageRef` and `backImageRef` onto the binding. A shoe
keeps its artwork in the display / outer-side / top channels, so **binding a shoe silently
discarded its artwork and then reported it as missing**, even though the operator had assigned it.
`setArrangerPieceGarmentArtwork` already mirrored all five channels onto existing bindings, so
binding was the odd one out. It now copies every channel, plus `artworkAspect`.

## 3. Synthetic alpha artwork added

Generated by `scripts/generate-alpha-garment-test-media.mjs`, a repeatable, dependency-free
script (PNGs are encoded with Node's `zlib`). Output lives in
`public/presence-spatial/internal-evidence/alpha-garments/`, alongside a `README.md` labelling it
as test media.

| `shirt-back-alpha.png` | 1,556 | as above, chevron + double hem stripe |
| `pant-front-alpha.png` | 1,734 | waistband, hips, two legs with an open crotch gap |

| **Total** | **10,976** | |

Properties, all asserted by test rather than asserted by me:

- Every pixel is **either fully transparent or fully opaque**, so `alphaTest` is unambiguous.
- All four corners are transparent. Measured transparent area: pant 36.8%, shirt 42.7%,
  generic 45.0%, shoe 55.6% — the test floor is 12%.
- Each outline varies in width by more than 25% down the image, so none is a padded rectangle.
- The pant has a genuine **interior hole** between its legs.
- Front and back differ in more than 2% of pixels — a ring emblem and one hem stripe on the
  front, a chevron and two stripes on the back.
- A `TEST` wordmark and an `F`/`B` face letter are baked in, painted only where the garment
  already is so the label can never add opaque pixels outside the silhouette.

**Public-safe and synthetic.** No photography, no brand marks, no licensed material, no real
product facts, no Mobstar creative. The attribution string on every asset reads
"Synthetic alpha-masked garment test artwork (internal evidence, not product artwork)".

## 4. The evidence fixture

`lib/presence/spatial/fixtures/alphaGarmentRack.ts`, loadable from the arranger via
**Load alpha garment rack**.

It is assembled by **replaying the real operator mutations** — create a Piece Library item, assign
garment artwork, bind to the rack — rather than by hand-writing bindings, so it cannot drift from
what the arranger UI produces. Those mutations use a fixed timestamp, so it is deterministic.

- One `presence.suspended-rack` host, arrangement derived as `rack-row`
- **Six garments**: shirt (front + back), shirt (front only, so the back-reuses-front fallback is
  exercised), pant (front + back), generic (front + back), shoe (display), and one deliberately
  **left with no artwork**
- One `open-link` action on Look 01
- Validates, compiles, saves and reloads with order preserved

## 6. What the alpha proves, and what it does not

Being precise about each piece of evidence, because they prove different things.

| Evidence | Proves | Does **not** prove |
|---|---|---|
| Unit tests decoding the PNGs | The source artwork genuinely carries alpha and non-rectangular silhouettes | Anything about the renderer |
| e2e `LEG_GAP_ROWS=59` | The artwork reached the WebGL lane and shaped what was drawn — the placeholder cannot produce an interior gap | Not by itself that the plane is transparent |
| e2e fill ratio < 0.75 | The garment does not fill its own bounding box | — |
| Carrier debug screenshot | The carrier is a **rectangular box larger than the garment**, while the garment is not rectangular — so the silhouette comes from the artwork, not the geometry | — |
| Carrier on/off pixel counts | Artwork is independent of carrier visibility | — |
| Control screenshot 28 + spot measurement | The alpha-preserving fix is load-bearing | — |

On the control: reverting the alpha-preserving fix leaves each garment sitting on a **dark opaque
card**. Measured at a point inside the shirt's plane but outside its silhouette, that region reads
**rgb sum 13.0 with the fix and 25.0 without it** — the card is roughly twice the brightness of
the room behind it. The difference is real but visually subtle *only because the fill colour
`#111318` is close to this room's own near-black*. In a lighter room it would be obvious.

Because that difference is small and depends on what is behind the garment, the automated guard
for §2.3 is a **source tripwire** asserting the opaque fill stays behind the `preserveAlpha`
guard, not a photometric threshold. That is stated plainly rather than dressed up as a pixel test
it cannot reliably be.

## 8. Saved JSON and payload

The saved layout is **10,735 bytes** against the 100 KB budget.

It stores **media ids only**. Asserted by test: no `data:image`, no base64 `data:` URL of any
kind, no `.glb`/`.gltf` path, no `presence pieces` source path, no signed-URL query strings, no
`http://`. The public path appears exactly once per asset, on the asset record, and the images are
served as ordinary static files from `public/`.

Hang profiles, slot transforms and hardware remain derived, never persisted.

## 9. Fallback behaviour

Unchanged and complete. The 390px semantic fallback carries all six looks in binding order with
piece type, captions and the Look 01 action link. Alpha artwork affects 3D rendering only.

## 11. What still fails or remains limited

- **The room is very dark**, so garments carry nearly all the visual weight and the difference
  between a transparent plane and a near-black opaque card is subtle to the eye. Lighting is
  unchanged by this pass.
- **The artwork is deliberately crude** — flat colours and geometric marks. It proves the alpha
  mechanism; it says nothing about art direction or final visual quality.
- **The shoe remains a proxy**: a low stand plus flat planes, not footwear geometry.
- The automated guard for the letterbox fill is a source tripwire, not a rendered assertion (§6).
- Inspection height is still article-agnostic.
- Sleeve artwork for shirts is still documented-but-unimplemented.
- The 6 pre-existing locator failures in `presence-spatial-object-model.spec.ts`, recorded in the
  previous evidence document, are untouched and remain.
