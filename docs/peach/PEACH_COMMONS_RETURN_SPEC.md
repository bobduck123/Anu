# PEACH Commons Return Specification

## Purpose

Return is the act of placing a Field's Yield back into the Commons with consent, attribution, access, preservation, and continuity. A Field is not complete merely because a post, event recap, or download exists. It is complete when the Yield becomes usable cultural inheritance.

## Commons Return Must Include

- Field summary.
- Seed.
- Soil/context.
- Vessels used.
- Gatherings held.
- Selected Contributions, if consented.
- Yield.
- Contributor credits.
- Steward notes.
- Support/funding note if appropriate.
- Related/descendant Fields.
- Future questions.
- Teaching/resource links if applicable.

## Return Workflow

1. Steward confirms the Field is in Yielding or ready to Return.
2. Steward identifies the final Yield artifact or artifacts.
3. Steward reviews all selected Contributions against consent and credit preferences.
4. Steward removes, anonymizes, or restricts any material that lacks permission.
5. Steward prepares Field summary, Seed, Soil/context, Vessels, Gatherings, credits, support note, and future questions.
6. Steward creates Commons entry.
7. Steward checks accessibility, source links, download/readability, and preservation format.
8. Steward publishes Commons entry and marks Field Returned.
9. Steward notifies contributors/supporters where appropriate.
10. Steward keeps a correction, takedown, and descendant Field path open.

## Public Commons Entry Structure

| Section | Required content | Private exclusions | Revision rules |
| --- | --- | --- | --- |
| Field summary | Title, Field ID, status, season, one-paragraph summary. | Internal notes, private sponsor terms. | Correct factual errors with visible update date. |
| Seed | Original Seed and any public revision note. | Internal rejected Seeds. | Preserve original; note material changes. |
| Soil/context | Public context, source trail, place/history notes. | Sensitive context, private identities, unsupported claims. | Add clarifications and source corrections. |
| Vessels used | Public Vessels with type, source, access, rights note, Field relevance. | Private or rights-restricted sources unless permission allows. | Update broken links and rights notes. |
| Gatherings held | Titles, dates/windows, formats, purpose, public notes/recordings if allowed. | Attendee lists, private chat, unconsented recordings. | Add transcripts/resources later if consent allows. |
| Selected Contributions | Only consented excerpts/artifacts with correct credit. | Private, held, rejected, withdrawn, or follow-up-unresolved material. | Remove or revise on valid takedown/correction request. |
| Yield | Readable/viewable/downloadable work and format notes. | Drafts unless intentionally published with consent. | Version updates allowed; keep release history. |
| Contributor credits | Names/chosen credits, anonymous acknowledgements, maker/steward credits. | Contact info, private legal names, withheld identities. | Correct credit errors promptly. |
| Steward notes | Method, editorial criteria, limits, decisions, what the Field does not claim. | Private contributor details, internal disputes. | Add correction notes if decisions change. |
| Support/funding note | Funders/patrons if acknowledged; what support enabled; editorial independence note. | Anonymous supporters, private amounts unless agreed. | Update for accuracy. |
| Related/descendant Fields | Parent/child Field links and continuation status. | Speculative internal plans. | Add descendants later. |
| Future questions | Questions that emerged and could become Seeds. | Sensitive unresolved matters. | Add/refine as Field is taught or reused. |
| Teaching/resource links | Teaching kit, citation, method notes, reuse guidance if applicable. | Restricted materials. | Add resources later. |

## Permissions And Consent Checks

Before Return, steward must verify:

- every public Contribution has consent for public display or Yield use;
- every credit matches contributor preference;
- anonymous material is stripped of identifying details where needed;
- youth/child material has follow-up and safeguarding review;
- third-party Vessels respect rights/access limits;
- sponsor/funder notes do not imply editorial control;
- private material remains private;
- withdrawn material is excluded from future use where feasible.

## What Remains Private

- Private-to-steward Contributions.
- Internal discussion notes unless explicitly prepared for public release.
- Contributor contact details.
- Youth/child details unless specifically cleared.
- Sensitive material without publication consent.
- Rejected or held Contributions.
- Sponsor contract details not intended for public disclosure.
- Raw exports and operational records.

## What Can Be Revised Later

- Broken Vessel links.
- Accessibility formats.
- Teaching/resource links.
- Future questions.
- Corrected credits.
- Factual corrections.
- Takedown/removal of selected material where consent or safety requires.
- Links to descendant Fields.

Substantive revisions to the Yield should preserve version history.

## Descendant Fields

A Returned Field may inspire a descendant Field when:

- a future question is strong enough to become a new Seed;
- the original Return identifies unresolved tension or continuation;
- participants, stewards, or institutions request a new season;
- a Yield creates new source material for further study.

Descendant Fields must have their own Field ID, steward, Seed, consent model, support path, and Return plan. They must not silently reopen old consent.

## Return Failure Cases

Return must be delayed or restricted if:

- selected material lacks consent;
- credits are unresolved;
- rights for Vessels or media are unclear;
- Yield artifact is not accessible;
- support/funding note is misleading;
- contributor withdrawal request is unresolved;
- the Field does not yet have a usable Yield.

If a Field cannot Return, archive it with a public explanation that does not expose private material.
