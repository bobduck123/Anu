# PEACH Phase 1 Routes

## Purpose

This document defines the Phase 1 public and steward/admin routes. It is a product surface specification, not UI design. Routes should support one excellent Field and keep PEACH centered on cultural cultivation, not ecommerce, events, social feeds, or content posting.

Route paths are recommended placeholders and can be adapted to the final framework.

## Steward/Admin Routes

| Route | Purpose | User type | Required data | Actions | Empty states | Success states | Failure states | Phase 1 minimum | Phase 2 expansion |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| `/admin/fields/[fieldId]` Field editor | Create/edit Field shell and status. | Steward, admin. | Field, Seed, Soil, status, steward, support copy, Return plan. | Edit Field; preview; change status; publish update. | New Draft with checklist. | Field reaches Upcoming/Open only when checklist passes. | Public Field missing Seed, consent, steward, or Return plan. | Single Field editor. | Multi-Field dashboard, workflow approvals. |
| `/admin/fields/[fieldId]/vessels` Vessel manager | Manage Field entry sources. | Steward. | Vessels and Field status. | Add/edit/reorder/remove Vessels; set rights notes. | No Vessels yet; show required 3-5 before Open. | Public Vessels display correctly. | Book/product catalogue drift; rights notes missing. | CRUD list for Vessels or structured config. | Suggested Vessels, annotations. |
| `/admin/fields/[fieldId]/gatherings` Gathering manager | Manage interpretive moments. | Steward. | Gatherings and Field. | Schedule/edit/cancel; publish access details; add recording/notes. | No Gatherings; show launch requirement. | Gathering visible with purpose and access details. | Event detached from Field; cancellation not logged. | CRUD or structured event records. | RSVPs, attendance, reminders. |
| `/admin/fields/[fieldId]/prompts` Tending prompt manager | Manage contribution prompts. | Steward. | Prompts, accepted types, consent copy. | Create/edit/pause/close prompts. | No prompts; show required 2-3 before Tending. | Prompts visible and submissions routed. | Prompt edits lose context; unsafe prompt. | Prompt CRUD with audit. | Conditional prompts, cohorts. |
| `/admin/contributions` Contribution review queue | Review Contributions before any use. | Steward, reviewer. | Pending/held/selected Contributions, consent records, contributor info. | Filter, inspect, accept/hold/reject/private/select/publish. | No pending Contributions. | Decision stored with actor/time/reason. | Unreviewed publication; consent mismatch. | Required queue. | Assignment, bulk triage, advanced safety workflows. |
| `/admin/contributions/[id]/consent` Consent/credit review | Confirm permission and attribution. | Steward, admin. | Contribution, Contributor, ConsentRecords. | Add follow-up; supersede consent; mark withdrawal/dispute; set credit. | Missing ConsentRecord blocks review. | Consent active and compatible with intended use. | Raw consent overwritten; Level 6 published without follow-up. | Required detail surface. | Contributor consent portal, evidence uploads. |
| `/admin/fields/[fieldId]/yield` Yield editor | Define and release the cultural work. | Steward, maker. | Yield, selected Contributions, consent checklist, credits. | Edit Yield metadata; link artifact; update progress; mark released. | No Yield yet; require planned Yield before Open. | Yield released only after checklist. | Missing consent/credits/accessibility. | Structured editor/checklist. | Multiple Yields, editions, production workflow. |
| `/admin/fields/[fieldId]/return` Commons Return workflow | Return Yield/Field to Commons. | Steward, admin. | Field, Yield, CommonsEntry draft, consent/credit/source checklist. | Build CommonsEntry; run checks; publish Return; set Field Returned. | No released Yield; block Return. | CommonsEntry published with consented material. | Private material exposed; Return claimed without artifact. | Required checklist/workflow. | Commons publishing tools, lineage graph. |
| `/admin/support` Support transaction/reporting view | Record and report values-aligned support. | Steward, admin. | SupportTransactions, Patrons/Supporters, Field/Yield associations. | Record manual support; view totals; manage acknowledgements; export. | No support yet. | Support metadata complete and transparent. | Payment data exposed; sponsor control implied. | Manual/external payment metadata view. | Native payment webhooks, dashboard, reports. |

## Route Guards

- Public routes must respect Field and object visibility.
- Admin routes require authenticated steward/admin role.
- Contribution submission must be available only when Field/prompt status allows or must show closed status.
- Support routes can link to external/manual payments, but metadata must be captured.
- Commons Return route must block publication when consent checks fail.
