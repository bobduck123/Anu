# PEACH Gate 13 Product Learnings

Date: 2026-07-31

## Pilot mode

Surrogate-only. These are rehearsal learnings from the surrogate loop, not real trusted-adult feedback.

## Distinction from anti-patterns

PEACH still feels distinct from:

- book club;
- bookstore;
- events site;
- ecommerce storefront;
- affiliate or dropship site;
- generic content platform;
- social feed;
- Substack or Patreon clone.

The strongest distinction is the Field -> Seed -> stewarded Contribution -> consent -> possible Yield -> Commons Return sequence.

## Field

`Field` is promising but needs a compact explanation before the participant sees forms.

Surrogate note: Participant B understood `Field` after reading the Seed, not before.

## Seed

The Seed creates intrigue:

`What does a community learn when it studies itself as seriously as institutions study it?`

The Seed should stay central. It prevents PEACH from becoming generic submission software.

## Contribution

Contribution feels meaningful when it is tied to the Seed. The intake labels still risk feeling formal. A small example Contribution could reduce friction.

## Consent

Consent is clear but dense. It should remain explicit, but the UI needs plainer summaries:

- private to stewards;
- internal discussion only;
- possible Yield later;
- follow-up required;
- nothing public now.

## Support

Support feels values-aligned because it is framed as manual follow-up for stewardship, access, Field work, and Commons preservation.

The no-payment boundary is legible and must stay prominent.

## Steward review

The steward review flow is usable in surrogate mode:

- pending queue is visible;
- detail view includes body and consent;
- review status update works;
- public display remains false.

Steward notes should become more structured before a real pilot.

## Commons Return

Commons Return is legible after an example. Without an example it remains abstract.

Suggested copy change:

`A Commons Return is the approved work, method, or learning that comes back to the community after consent and steward review.`

## Confusions

- `Commons Return` needs a short example.
- `Field` needs one-line explanation near first use.
- withdrawal timing needs plainer wording.
- consent labels are accurate but heavy.

## UI changes

- Add a short glossary block for Field, Seed, Yield, Commons Return.
- Add a private-pilot status strip near contribution and support forms.
- Add plainer consent option helper text.
- Add a support intent confirmation that repeats no payment was taken.
- Add steward note structure for held/rejected decisions.

## Copy changes

- Keep the PEACH definition.
- Keep the anti-pattern guardrails.
- Add one concrete Yield/Commons example.
- Replace any wording that sounds like publication, checkout, subscription, feed, or campaign conversion.

## What must not change

- No public contribution display.
- No real payments.
- No youth or sensitive material.
- Manual steward review.
- Consent-first framing.
- Field/Seed/Yield/Commons vocabulary.
- PEACH as cultural cultivation, not content capture.
